# 交互式导航 (Interactive Navigation) — 项目规划

**创建日期：** 2026-04-11  
**更新日期：** 2026-04-11  
**状态：** 规划阶段

---

## 1. 项目概述

### 1.1 研究目标

在传统机器人导航（语义地图引导 / SLAM 框架）基础上，增加**环境交互能力**，使得机器人能够：

1. 感知场景中的可交互对象（门、冰箱、衣柜、抽屉等铰接对象）
2. 判断交互属性与交互类型（开关 / 按钮 / 推拉）
3. 将交互信息链接到场景拓扑/语义图中，构建"交互图"
4. 利用交互信息改进导航规划，完成更复杂的导航/探索任务

### 1.2 核心定位

> **聚焦于交互图的构建与感知，操作部分不作为考核点。**

- ✅ 交互对象识别与分类
- ✅ 交互属性的语义地图表征
- ✅ 交互感知的导航规划
- ❌ 操作控制策略（使用 oracle / 现有方法代替）

### 1.3 差异化创新

| 维度 | 现有工作 | 本项目 |
|------|---------|--------|
| 地图表征 | 3D 语义地图 / 场景图 | 在场景图上增加**交互属性边** |
| 交互感知 | 单次 affordance 检测 | 持续维护交互状态 |
| 任务规划 | 导航 OR 操作 | 导航 → 交互 → 导航 交替执行 |
| 操作处理 | 深度耦合控制策略 | Oracle 交互，聚焦感知 |

## 2. 课题立意论证

### 2.1 必要性论证

1. **任务不可达性**：现实环境中大量目标被可交互对象阻塞（门关着），纯导航成功率存在不可突破的上界
2. **效率提升**：交互能力允许"穿门抄近路"而非绕行走廊，显著缩短路径
3. **主动感知增益**：打开门/抽屉 = 获取新的观测空间（active perception）
4. **现实需求对齐**：家庭服务机器人、仓储机器人都需要"能走到 → 能做到"的跨越

### 2.2 可量化指标

- 在 ProcTHOR / HM3D 场景中，统计被可交互对象阻塞的目标比例
- 交互导航 vs 纯导航的路径效率对比（SPL / SFT / 路径长度）
- 交互对象识别准确率 & 交互类型分类准确率

### 3.2 研究空白

1. **交互状态持续跟踪**：现有工作把交互视为一次性事件，缺乏状态变化的持续维护
2. **多步交互链规划**：到达目标可能需要连续多次交互，现有框架缺乏长链规划
3. **交互代价建模**：不同交互操作的难度和时间成本不同，导航规划中缺乏交互代价
4. **统一的地图交互层设计**：缺乏在语义地图中优雅增加交互层的方法

## 4. 技术方案

### 4.1 系统架构

```
┌─────────────────────────────────────────────────┐
│                  感知层 (Perception)              │
│  VLM 开放词汇检测 → 交互对象识别 → 交互类型分类    │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│               地图层 (Map)                        │
│  语义地图 + 交互属性标注 + 交互状态跟踪            │
│  场景图节点: Room / Object / InteractionEdge      │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│               规划层 (Planner)                    │
│  LLM 驱动的交互感知导航规划                       │
│  考虑交互代价的路径搜索                            │
└──────────────────────┬──────────────────────────┘
                       ▼
┌─────────────────────────────────────────────────┐
│               执行层 (Executor)                   │
│  导航策略 + Oracle 交互指令                       │
│  交互成功 → 更新地图状态 → 继续导航               │
└─────────────────────────────────────────────────┘
```

### 4.2 地图交互层设计

在现有语义场景图基础上，增加**交互属性边 (Interaction Edge)**：

```
Room_A --[contains]--> Door_1 --[can_open]--> Room_B
                        |
                   [interaction_type: push/pull]
                   [interaction_state: open/closed/locked]
                   [interaction_cost: low/medium/high]
```

**节点属性：**
- Object: 类别、位置、几何信息
- InteractionEdge: 交互类型（push/pull/slide/press）、交互状态、交互代价

### 4.3 交互类型分类

| 交互类型 | 典型对象 | 检测方式 |
|---------|---------|---------|
| Push/Pull（推拉） | 门、柜门 | 铰链方向 + 把手位置 |
| Slide（滑动） | 抽屉、推拉门 | 滑轨方向检测 |
| Press（按压） | 按钮、开关 | 小型刚性部件 |
| Twist（旋转） | 旋钮、水龙头 | 旋转关节检测 |

## 5. 仿真平台选型

### 5.1 选型结论：MolmoSpaces

| 平台 | 规模 | 交互支持 | 导航支持 | 物理真实度 |
|------|------|---------|---------|-----------|
| AI2-THOR | ~120 场景 | ✅ | ✅ | ⚠️ 一般 |
| Habitat | 大规模 | ❌ | ✅✅ | ❌ 无物理 |
| BEHAVIOR-1K | 50 场景 | ✅✅ | ✅ | ✅ |
| **MolmoSpaces** | **230k 场景** | **✅✅** | **✅** | **✅ MuJoCo** |

**选择 MolmoSpaces 的理由：**
- 230k+ 多房间室内环境，解决"场景少"的问题
- 48k 可操作对象（含 articulated object），支持门、抽屉等交互
- 内置 **open-door** 任务，直接对应核心场景
- Simulator-agnostic（MuJoCo/Isaac/ManiSkill），物理仿真可靠
- open-source，可自定义 benchmark
- sim-to-real 相关性 R = 0.96

### 5.2 技术栈

- **仿真引擎：** MuJoCo（通过 MolmoSpaces）
- **机器人：** Franka Droid（移动底座 + 机械臂）
- **评估框架：** MolmoSpaces benchmark.json → eval_main.py → CSV
- **感知：** VLM (open-vocabulary detection) + 3D 重建
- **规划：** LLM 驱动

## 6. 评估方案

### 6.1 Benchmark 设计

基于 MolmoSpaces 框架，定义**交互式导航 benchmark**：

**任务定义：**
- 给定一个目标位置 / 目标物体
- 机器人需要导航到达，途中可能需要通过交互（开门等）才能到达
- 交互操作使用 oracle（假设成功执行）

**Episode 配置：**
- 从 ProcTHOR 多房间场景中采样
- 筛选包含门/可交互对象阻塞路径的场景
- 随机化目标位置和门的开关状态

### 6.2 评估指标

| 指标 | 说明 |
|------|------|
| **Navigation SR** | 导航成功率 |
| **Interaction Detection Acc** | 交互对象检测准确率 |
| **Interaction Type Acc** | 交互类型分类准确率 |
| **SPL** | Success weighted by Path Length |
| **SFT** | Success weighted by Floor Traversal |
| **Path Efficiency** | 交互导航路径长度 / 最短路径长度 |
| **Oracle SR** | 使用 oracle 交互后的最终导航成功率 |

### 6.3 Baseline 对比

| Baseline | 说明 |
|----------|------|
| Pure Navigation | 纯导航，不考虑交互（存在不可达上限） |
| Oracle Navigation | 已知所有门状态的最优导航（性能上界） |
| Random Interaction | 随机尝试交互 |
| **Ours (Interactive Scene Graph)** | 交互感知的导航 |
