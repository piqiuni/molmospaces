## 配置与口径

- H1-H10，10 worker 并行，seed=house，任务步数上限 500。
- `full_mllm_exploration`，初始门关闭、容器强制关闭，录制开启。
- `organized_depth`，pointcloud stride=1，原生 OpenBLAS/OMP/MKL 线程各 1。
- 两张 A100，模型 `qwen3.6-35b-a3b-fp8`。本轮专用 ROS 端口 16201-16210，结束后已释放。
- 仿真控制周期 0.2 秒，视频 15 fps；没有调整物理子步、交互步数、站位距离或到达容差。
- 秒/step 按实际完成步数加权；P95 汇总所有实际任务步。整批/场景墙钟包括启动、仿真、关闭、离线分析和视频生成。
- 覆盖率是十场算术平均；本轮与 R5 的 GT 分母、半径、分辨率及批处理参数逐场一致。
- 交互次数是唯一已发布命令，不是不同物体数。门物理成功不包含静态通道确认；容器类包含冰箱交互和抽屉扫描。失败与待返回分开记录。

## 跳过等待验证

仅当交互控制器已暂停导航，且原有本帧地图 ready 等待满足时，使用 `navigation_hold`，不再等待新的导航指令。
原有 ready 失败处理、传感器发布、fresh-command gate、step sync、录制 ACK、task step、交互回调及视角动作仍保留。

## 质量与限制

- H3 明显退化：覆盖率 45.73% -> 27.82%，门成功 1 -> 0，286 步提前结束。该场 navigation_hold 为 0，不能直接将早停归因于这一快路径。
- H10 覆盖率 43.22% -> 61.06%，与 H3 的下降在均值中近乎抵消。总体覆盖率持平不代表逐场正常。
- H1 覆盖率下降 2.94 个百分点，但新增门和抽屉各一次成功；其平均 step 耗时增加 18.2%，两轮交互工作量不同。
- H8 门成功 0 -> 1，但容器成功 1 -> 0。不能宣称该场全面改善。
- M1 请求 237/237 无请求错误或超时，但这不等于每次视觉状态判断正确。
- 日志审计未发现运行期崩溃；H2/H3/H4/H6/H8/H9/H10 仍有关闭期内存释放告警。不能用退出码 0 代替算法验收。
- 十个视频全部 exact-step 对齐，4657 帧完整解码通过，无缺帧；15 fps。原始视频与日志不纳入 Git。
- 本报告是当前性能记录，**不是“逐场性能无退化”验收通过**。MLLM/异步调度有波动，本轮没有完成单变量重复 A/B。
